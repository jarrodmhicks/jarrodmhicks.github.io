# A static website for academics

A colorful, fast, keyboard-friendly personal site for a researcher. It has a home page, an About page with a career path, a searchable list of papers, a searchable list of talks and posters, a "Lately" page, a consulting page and a contact page.

There is **no framework, no database and no dependencies**. The whole site is plain HTML, CSS and a little JavaScript, generated by one script (`build.js`) from a handful of small text files. You edit the text files, push to GitHub, and the site updates itself.

```
edit a file in data/  →  push to GitHub  →  the Action runs build.js  →  site is live (about a minute)
```

## Why it is built this way

- **Content lives in data, not in HTML.** Your publications are an ordinary `.bib` file. Your talks are a JSON list. You never touch markup to add a paper.
- **One build script you can read.** `build.js` is a single file with no packages to install (it needs only Node 16 or newer). If you want to change how something looks or works, you can find it.
- **Mistakes are caught before they go live.** The build checks every file. If something is wrong it stops with a plain message (for example `data/presentations.json (entry 4: My Talk): missing or invalid "date"`), the GitHub Action turns red, and the live site stays exactly as it was.
- **Fast and private.** Fonts are hosted on the site itself, nothing loads from third-party servers, and analytics are off unless you turn them on.

## What you get

- **Papers page.** Reads a BibTeX file. Search, filter by topic (pick several), filter by year, sort by year or by citations. Authors, venues, years and topics on each card are clickable too: clicking one adds it as a chip inside the search box, so you can combine them (several authors, one venue, one year, several topics). Remove a chip with its ✕ or with Backspace in the empty box; "clear all" or `Esc` resets everything. Each paper has links (DOI, PDF, code, data), a "cite" button that shows BibTeX and copies a formatted citation, and a "new" sticker for recent papers. Citation counts can be filled in automatically (see below).
- **Presentations page.** A list of talks and posters grouped by year, with the same search, filters and clickable card fields, plus an "upcoming" group that fills and empties itself by date.
- **Summary stickers** at the top of both pages (papers, h-index, citations, talks, conferences, cities, and so on), computed for you.
- **About, Lately, Consulting and Contact pages**, each driven by a small JSON file.
- **Keyboard shortcuts** for everything (press `?` on the site).
- **Small touches:** animated stickers and cards (they switch off for visitors who ask for reduced motion), a spam-resistant email button, a hidden Konami-code surprise, and a sitemap and `robots.txt` generated for you.

The look is deliberately bold: thick outlines, offset shadows and a seven-color palette (red, orange, yellow, green, blue, purple, pink). The site is light-only by design.

## Quick start

1. **Get the code.** Fork or copy this repository. For a user site the repository must be named `<your-username>.github.io`.
2. **Turn on GitHub Pages.** In the repository go to **Settings → Pages → Build and deployment → Source** and choose **GitHub Actions**. For a custom domain, set it on that same page.
3. **Make it yours.** Edit the files in `data/` (described below). Replace the portrait at `assets/img/jarrod.jpg` (square, about 800 × 800) with your own photo. The portrait path is set in `build.js`; search for `jarrod.jpg` if you want to rename it.
4. **Push to `main`** (or `master`). The first run appears under the repository's **Actions** tab. When it is green, the site is live.

You do not need to install anything to edit. You can change any file on github.com with the pencil button and commit; the Action does the rest.

### Preview on your computer (optional)

```
node build.js --local        # builds into dist/ with relative links, so you can open dist/index.html directly
```

or, for a real local server at http://localhost:8000:

```
node build.js
python3 -m http.server 8000 --directory dist
```

(`npm run preview` and `npm run serve` do the same.) Never commit the `--local` build; the Action always makes the real one. `dist/` is in `.gitignore`.

## How it works

`build.js` does the following every time it runs:

1. Reads everything in `data/` and checks it. Problems are collected and reported together, so you can fix them in one pass.
2. Turns the data into pages (`index.html`, `about/`, `papers/`, `presentations/`, `lately/`, `consulting/`, `contact/` and `404.html`), plus `sitemap.xml` and `robots.txt`.
3. Copies `assets/` (CSS, JavaScript, fonts, images, PDFs) into `dist/`.

The GitHub Action in `.github/workflows/deploy.yml` runs this on every push, on demand, and once a day. The daily run matters: "upcoming" talks, "days since" counters and the "new" paper sticker all depend on today's date, and a daily rebuild keeps them current without you doing anything.

All interactive behavior (search, filters, keyboard shortcuts, the cite box, the email button) is in `assets/js/site.js`. All styling is in `assets/css/site.css`, with the colors and fonts defined once at the top as CSS variables.

## What is where

```
data/                              everything you edit (see below)
  site.json                        your name, intro, About text, page subtitles, options
  papers/papers.bib                your publications, as BibTeX
  presentations.json               your talks and posters
  topics.json                      the allowed topic names
  timeline.json                    the career path on the About page
  lately.json                      the Lately page
  consulting.json                  the Consulting cards
  links.json                       the social stickers on the Contact page
assets/                            copied to the site as-is
  css/site.css                     all styling
  js/site.js                       all interactive behavior
  fonts/                           the three typefaces (free, SIL Open Font License)
  img/                             your portrait
  papers/                          PDFs of your papers (optional)
  presentations/                   posters and slides (optional)
build.js                           the build script
tools/fetch-citations.js           optional: looks up citation counts
.github/workflows/deploy.yml       the Action that builds and publishes
```

Anything in `assets/` is published under the same path, so `assets/papers/my-paper.pdf` is available at `/assets/papers/my-paper.pdf`. Link to it that way, starting with a slash.

## Editing your content

### `data/site.json`

| Key | What it does |
| --- | --- |
| `name` | Your name, used in the title, header and footer |
| `eyebrow` | The small line above your name on the home page |
| `url` | Your site's address, used in the sitemap |
| `email` | Your email address (stored encoded; see "Email and analytics") |
| `me` | How your name appears in author lists, for example `F. Author`. Authors who match it (same last name and first initial) are shown in bold, so `F. Author` and `First Author` both match |
| `tagline` | A list of lines shown large on the home page |
| `intro` | One or two sentences on the home page |
| `description` | The text search engines show |
| `about` | A list of paragraphs for the About page |
| `ledes` | The short line under each page title (`about`, `papers`, `presentations`, `consulting`, `contact`, `lately`). Set one to `""` or delete it and no line appears |
| `hide` | Optional list of pages to switch off, for example `["consulting"]`. A hidden page gets no tab, no file and no sitemap entry |
| `analytics` | See "Email and analytics" |

Text fields (`intro`, `about`, `ledes`, Lately items, Consulting text) accept two bits of markup: `[link text](https://example.com)` for a link and `**bold**`. Links to other sites open in a new tab, and links to your own pages work too (`[my papers](/papers/)`). Nothing else is interpreted.

### Papers: `data/papers/*.bib`

Papers are ordinary BibTeX. Export from Google Scholar, your reference manager or a publisher's "cite" button, paste the entries into `data/papers/papers.bib` (any `.bib` file in that folder is read, so you can split them up), and then add a `topics` line to each entry. That one field is required:

```bibtex
@article{author2027example,
  title     = {A descriptive title for the first example paper},
  author    = {Author, First and Author, Second and Author, Third},
  journal   = {Journal of Examples},
  volume    = {12},
  number    = {3},
  pages     = {100--110},
  year      = {2027},
  month     = {mar},
  doi       = {10.1234/example.2027.001},
  topics    = {vision, methods},
  pdf       = {/assets/papers/author2027example.pdf},
  code      = {https://github.com/example/example-code},
  data      = {https://osf.io/example}
}
```

Fields the site understands:

| Field | Notes |
| --- | --- |
| `title`, `author`, `year` | Required. Authors can be `Last, First and Last, First` or `First Last and First Last` |
| `journal`, `booktitle`, `school` | The venue shown on the card (the first one present is used) |
| `volume`, `number`, `pages` | Shown after the venue |
| `doi` | Just the DOI, or a full `https://doi.org/...` link. Also used to look up citation counts |
| `topics` | **Required.** One or more names from `data/topics.json`, separated by commas |
| `pdf`, `code`, `data` | Optional links. A local file uses a root-relative path like `/assets/papers/name.pdf`. PDFs open in a new tab |
| `month` | Optional (`mar` or `3`). Makes the "new" sticker accurate (see below) |
| `status` | Optional. `preprint` marks a paper as not yet journal-published (it is left out of the "journals" count) |
| `citations` | Optional. A number, if you want to type the count yourself instead of fetching it |
| `new` | Optional. `true` or `false` to force the "new" sticker on or off |
| `equal` | Optional. A number (2 to 10): the first that many authors contributed equally. They get an asterisk and the card shows "* denotes equal contribution". The copied BibTeX gets a note saying so, unless the entry already has a `note` |

The extra fields (`topics`, `pdf`, `code`, `data`, `status`, `citations`, `new`, `equal`) are stripped out of the BibTeX that visitors copy from the cite box, so they get a clean entry. `month` and `doi` stay in.

**Entry types.** `@article`, `@inproceedings` and `@phdthesis` are recognised and set the type of the copied citation. Any other type is treated as an article.

**The "new" sticker.** A paper that has no citation badge yet and is recent gets a pink "new" sticker. With a `month` it means published within the last seven months; with only a year it means "this calendar year". Once a paper has citations, the yellow citation badge replaces the sticker.

**Citation counts (optional).** `tools/fetch-citations.js` asks [OpenAlex](https://openalex.org) for each paper's citation count (looked up by DOI) and writes `data/citations.json`, which the build reads. The GitHub Action runs it before every build. To enable it, get a free OpenAlex API key and add it to the repository under **Settings → Secrets and variables → Actions** as `OPENALEX_API_KEY`. Without a key the step is skipped and the site simply shows no counts. `data/citations.json` is in `.gitignore` because it is regenerated each time. To try it on your own machine: `OPENALEX_API_KEY=your_key node tools/fetch-citations.js`.

You can also describe a paper as a small JSON file in `data/papers/` (fields: `title`, `authors`, `venue`, `year`, `topics`, optional `details`, `links`, `citations`); `.bib` is the recommended route.

### Presentations: `data/presentations.json`

One JSON list, one object per talk or poster. Order does not matter; the site sorts by date, newest first.

```json
[
  {
    "title": "A descriptive title for the first example talk",
    "type": "talk",
    "venue": "Example Society Annual Meeting (ESAM)",
    "city": "Springfield, IL",
    "date": "2027-03",
    "conference": true,
    "authors": ["First Author", "Second Author", "Third Author"],
    "topics": ["vision"],
    "links": {
      "slides": "/assets/presentations/example-2027-slides.pdf",
      "video": "https://www.youtube.com/watch?v=XXXXXXXXXXX"
    }
  },
  {
    "title": "A poster with no links yet",
    "type": "poster",
    "venue": "Example University Research Day",
    "date": "2026-11-14",
    "conference": false
  }
]
```

| Field | Notes |
| --- | --- |
| `title`, `type`, `venue`, `date` | Required. `type` is `talk` or `poster`. `date` is `YYYY-MM` or `YYYY-MM-DD` |
| `city` | Optional. Counted once per distinct city in the "cities" sticker. Leave it out for online events |
| `conference` | `true` for a conference or meeting, `false` for something like a department seminar. Feeds the "conferences" sticker |
| `authors` | Optional list. If left out, it defaults to you (`me` in `site.json`) |
| `topics` | Optional list from `data/topics.json` |
| `links` | Optional. Any of `slides`, `poster`, `video`, `code`, `data`, `demo`. Empty ones are left off |
| `placeholder` | Optional. `true` marks an entry as a stand-in; every build lists the placeholders still left |

A talk is shown as **upcoming** until its date has passed (the whole month if you gave only a month). Presentations can also be split into one JSON file each in a `data/presentations/` folder; both sources are merged. Do not put a list file inside that folder.

### Topics: `data/topics.json`

A plain list of the allowed topic names:

```json
["vision", "methods", "sound", "behavior"]
```

You assign topics to papers and presentations by name, and a typo is caught by the build. Two rules keep this tidy:

- **Only topics that something actually uses become filters**, and each page lists its own (Papers shows the topics of papers, Presentations the topics of talks). You can keep a large list of allowed names without clutter.
- **Colors are automatic.** Used topics are sorted A to Z and given the seven site colors in order, then the colors repeat. The same topic has the same color on both pages. Inside each card, topics are also sorted A to Z.

Visitors can select several topic filters at once; an item must have all of them. Choosing "all" clears them.

### About: `data/timeline.json`

The career path on the About page, newest first:

```json
[
  { "when": "2025 – now", "title": "Postdoctoral fellow", "where": "Example University" },
  { "when": "2019 – 2025", "title": "PhD, Example Science", "where": "Another University" }
]
```

Each step becomes a sticker showing its end year, or `now` when the `when` text does not end in a year. The full `when` text sits underneath.

### Lately: `data/lately.json`

A small "what I'm up to" page. One entry per colored label (one word each, up to seven). Items are listed **newest first**: the first one is shown and the arrows page back through the rest. To add something, put it at the top of its list.

```json
[
  { "label": "reading", "items": ["The newest thing.", "An older thing.", "An even older thing."] },
  { "label": "making",  "items": ["A project, with a [link](https://example.com)."] }
]
```

The footer shows "Last updated", taken automatically from the newest commit that touched `data/`.

### Consulting: `data/consulting.json`

A set of sticker cards, in order, colored by position:

```json
{
  "cards": [
    {
      "label": "check",
      "icon": "check",
      "title": "Want a second pair of eyes?",
      "text": "A sentence about what you offer.",
      "example": "e.g., a short example (optional)"
    }
  ]
}
```

`icon` is one of `check`, `explain`, `teach`, `demo`, `test`, `guest` or `sources`. To remove the whole page, add `"hide": ["consulting"]` to `site.json`.

### Contact: `data/links.json`

The social stickers that follow the Email sticker, in rainbow order:

```json
[
  { "name": "YouTube", "icon": "youtube", "url": "https://youtube.com/@example" },
  { "name": "Bluesky", "icon": "bluesky", "url": "", "soon": true }
]
```

`icon` is one of `youtube`, `instagram`, `tiktok`, `bluesky`, `threads` or `x`. A sticker with an empty `url` is left off, unless it has `"soon": true`, which shows it greyed out and badged "soon". When the profile exists, fill in `url` and delete `"soon": true`.

### Email and analytics

- **Email.** The Email sticker copies your address and shows a small notice with an "open mail app" button (on phones it opens the mail app directly). The address is stored encoded in the page and decoded by a script on click, so simple scrapers do not find it. Without JavaScript the sticker does nothing.
- **Analytics (optional).** In `data/site.json`, put a [GoatCounter](https://www.goatcounter.com) code in `analytics.goatcounter` (for `example.goatcounter.com`, use `"example"`), or a Cloudflare Web Analytics token in `analytics.cloudflare`. Empty means no tracking script is added at all. Local preview builds never include it.

## Customizing the design

- **Colors, fonts and sizes** are CSS variables at the top of `assets/css/site.css`. The seven palette colors also appear in `build.js` (`RAINBOW`, `TOPIC_COLORS`, the tab list).
- **The summary stickers.** `PAPER_STATS` and `PRES_STATS` in `build.js` list which totals appear in each page header, in order. A comment above them lists every available total (for example `h-index`, `most cited`, `with code`, `years active`, `countries`, `days to next`).
- **Which pages exist and their order.** The tab list is `ALL_TABS` in `build.js`. Use `hide` in `site.json` to switch pages off without editing code.
- **Fonts** are self-hosted variable `woff2` files in `assets/fonts/` (Fraunces for display type, Inter Tight for text and JetBrains Mono for labels), so nothing loads from Google. All three are free under the SIL Open Font License.

## Keyboard shortcuts

`1`–`7` jump to the pages, `/` searches (from any page it opens Papers with the search box focused), `?` shows the full list and `Esc` clears the search and any filters. In the search box, `Enter` selects the top result. On Papers and Presentations, `n` or `↓` selects the next card, `b` or `↑` the previous one, `←` and `→` move along the selected card's links and `Enter` opens the highlighted one, `c` opens the BibTeX box, and `v` views the card (a paper's PDF, or its DOI if there is no PDF; a talk's slides, or its video). You can also click a card to select it. On the home page you can grab the badge, drag it and let go, and it swings like a pendulum. On Lately, `↑` and `↓` choose a row and `←` and `→` page it. The shortcut list is also linked in the footer (hidden on phones).

## Troubleshooting

- **The Action is red.** Open the failed run under the **Actions** tab. The message names the file and entry to fix. Common ones: a topic that is not in `topics.json`, a missing required field, a date that is not `YYYY-MM`, or a JSON typo such as a missing comma or an extra trailing one.
- **The site did not change.** Check that Pages is set to the **GitHub Actions** source and that the run finished green. Then hard-refresh your browser.
- **A list file in the wrong folder.** `presentations.json` goes directly in `data/`, not inside `data/presentations/`. Papers go in the `data/papers/` folder.
- **A PDF link does nothing.** Local files must live under `assets/` and be linked from the site root, like `/assets/papers/name.pdf`. The file name is case sensitive.
- **Large PDFs.** Everything in `assets/` is stored in your repository. A few dozen megabytes is fine; if you have hundreds of large files, link to them elsewhere instead.
